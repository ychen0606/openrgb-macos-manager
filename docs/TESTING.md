# 验证范围

## 自动检查

执行 `./scripts/check.sh`：

- Python：多控制器明确选择、身份歧义拒绝、音箱能力校验、音乐效果仅绑定所选区域。
- Python：默认拒绝覆盖、保留用户设置与 default 配置、备份旧配置、部分写入失败恢复。
- Swift：缺失设备配置的错误、逐通道亮度缩放、关灯清零、原始配置保留、设置保存与范围校验、控制器身份歧义拒绝。
- Shell：脚本语法检查。
- Swift：原生应用编译、Info.plist 校验、签名完整性检查。

GitHub Actions 在 macOS runner 上执行相同检查，并额外交叉编译 Intel 版本。编译通过不等于已验证该 runner 或另一种 CPU 架构的 RGB 硬件兼容性。

## 原始本机版本的硬件验证

公开整理前的 2.0 build 4 曾在 Intel 黑苹果（Hackintosh）/ macOS 26.7.1、Gigabyte IT5701、USB AUDIO、OpenRGB 1.1 + Effects Plugin 1.1、BlackHole 2ch 0.7.1 上完成以下实测：

- 普通和 Direct 模式的红、蓝、绿切换。
- 同一种颜色从 100% 到 10% 明显变暗，用户目视确认。
- 音乐播放时灯光跟随，暂停后变暗，用户确认。
- 菜单栏音量和键盘音量键有效，音乐效果持续运行。
- OpenRGB 运行但 SDK 未启动时，约 6.7 秒恢复连接。
- 进程退出后，约 15.2 秒自动恢复保存的模式。
- 关闭 OpenRGB 窗口后保留 SDK 连接。

这些耗时是当次观测值，不是时延承诺。公开版 2.0.1 增加本机配置加载与安装工具，保留上述控制逻辑；发布整理期间没有替换正在运行的本机应用，也没有重新执行真实灯光和音量切换。自动检查覆盖新增配置逻辑。

## 新硬件人工验收

1. 在 OpenRGB 中确认目标机箱控制器能切换纯色和 Direct 模式。
2. 运行本机配置工具，确认设备身份唯一。
3. 普通灯光比较同色 100% / 10%，再验证关灯。
4. 音乐播放、暂停至少 3 秒，观察 LED，并确认音箱声音正常。
5. 调节菜单栏滑块、音量减/加和静音，确认灯效继续运行。
6. 普通/关灯后确认音乐捕获停止、声音直接输出。
7. 退出 OpenRGB，观察控制台恢复保存的模式；检查辅助功能授权与登录启动。

不要把私有设备 UID、完整本机配置或日志直接提交到公开 issue。报告时提供软件版本、控制器型号、现象和经过清理的错误信息即可。
