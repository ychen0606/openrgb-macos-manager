# 故障排查

## 显示 OpenRGB 未连接

点击所需模式，让控制台尝试恢复。检查 OpenRGB 已安装在 `/Applications/OpenRGB.app`、Effects Plugin 已启用、SDK 监听 `127.0.0.1:6742` 且允许本机控制。

macOS 对已运行的应用执行 `open --args` 不会补上新的启动参数，因此控制台会对“已运行但 SDK 未开启”的实例尝试正常退出再重启。OpenRGB 弹出的对话框可能阻止正常退出，需要先处理。

窗口显示时约每 5 秒检查 SDK，后台约每 30 秒检查。自动恢复失败后至少间隔 60 秒重试；模式按钮可以立即手动尝试。

关闭 OpenRGB 窗口会退出进程时，在它的设置中开启“关闭窗口时最小化”。隐藏的高级窗口可从 OpenRGB 自己的菜单栏图标选择“显示/隐藏”。

## 能选普通模式，但颜色或亮度没有变化

确认本机配置选中了正确的控制器，`default.json` 是当前设备导出的配置，并且存在 `Direct` 模式。程序会通过 SDK 进入 Direct，再显式写入全部 LED 的 RGB 值。

测试亮度时固定同一种颜色，比较 100% 与 10%。不同颜色的视觉亮度差异很大，不适合作为亮度是否生效的判断。

控制器身份重复、缺失或没有 Direct 模式时会拒绝操作。更换硬件后重新运行配置工具。

## 音乐有声音，但灯不跟随

先验证普通模式能控制灯，再逐项检查：

1. 系统默认输出是“OpenRGB 音乐同步”，默认输入是 BlackHole 2ch。
2. Effects Plugin 中实际选择 BlackHole 输入；模板索引 0 不保证在每台机器上对应它。
3. 双输出使用音箱和 BlackHole 同时播放，而非将通道串接成四声道。
4. OpenRGB 获得系统音频输入权限。
5. 降低过高的灵敏度，避免输入饱和导致常亮；播放后暂停约 3 秒比较。

修改插件输入后，将配置保存为“音乐同步”。控制台使用插件报告的效果状态和 CoreAudio 路由判断模式，无法自动证明灯真的跟随音乐，仍需要目视和耳听检查。

## 音量快捷键不能使用

macOS 原生双输出通常不支持系统音量调节。控制台通过音箱自己的 CoreAudio 音量接口实现调节；媒体键需要辅助功能授权。

以窗口显示“音量键已启用”为准。更新程序后，如果辅助功能已经打开但仍无效：移除旧 `OpenRGB Volume` 条目，重新添加 `~/Applications/OpenRGB Volume.app` 并开启。命令行进程的授权检查不能代替运行中 GUI 的权限状态。

如果菜单栏滑块也失败，确认选定音箱支持可写主音量和静音。部分 HDMI、蓝牙或只有分声道音量的设备不符合当前实现要求。

## 音频输入图标一直显示

音乐模式由 Effects Plugin 读取 BlackHole 虚拟输入，macOS 仍会显示音频输入指示。系统没有按设备单独隐藏此指示的正常设置。普通灯光和关灯模式停止音乐读取，系统可能暂时显示“最近使用”。

## 后台资源与流畅度

普通/关灯模式主要维持控制连接和状态检查；音乐模式还会分析音频并刷新 LED。30 FPS 会减少刷新次数，60 FPS 更流畅。

资源占用依赖硬件、插件、控制器数量和音乐效果。关闭窗口不会退出服务，也不会完全释放进程内存。需要完全停用时，先恢复普通模式，再退出控制台和 OpenRGB。
